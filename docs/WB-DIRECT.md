# WB 逐像素直驱

`player/k4-wb.c` 接收 800×600、30 fps、MSB-first 的 monob TCP 字节流。
每帧 60000 字节，1 表示白、0 表示黑。软件在每个 EPDC 扫描帧决定推白、推黑或不动。
它通过 `/dev/mem` 映射正在运行的驱动所分配的波形表与工作缓冲，使用 mxcfb 提交长 LUT。

## 工作缓冲格式

WB 每像素 16 位，小端；行步长由 EPDC 分辨率寄存器读出并按 4 像素对齐。

| 位 | 含义 |
| --- | --- |
| 15:12 | LUT 编号 |
| 11 | PARTIAL 处理中被选中的像素标记；FULL 不置位 |
| 10:8 | 本播放器保持为 0，未使用 |
| 7:4 | 目标灰度，动作表下标的高四位 |
| 3:0 | 当前灰度，动作表下标的低四位 |

每个扫描帧重读 WB，按 `(目标 << 4) | 当前` 索引活动 LUT 当帧的 256 字节动作表。
LUT 完成后 WB 保持原值，下次处理时旧目标成为当前灰度。
位定义来自探针实验；扫描机制依据 i.MX50 RM 24.3.8.1、24.3.8.4 与表 24-3。

## 合成表与启动

播放器先保存画布格式与关电延迟，设 REGION 自动刷新模式、Y8 画布和持续上电，
以真实 GC16 整屏刷白并等待完成。EPDC 已上电后才读寄存器：时钟门控时读寄存器
可能挂住总线并导致看门狗复位。

从当前温度档的硬件模式 4（A2）序列读取首个推黑、推白动作值，以推白非零帧数
作为 `nps`。在硬件模式 3 数据区放置一张长表，每帧均为目标 0 推黑、15 推白、
其它目标不动，对所有当前灰度一致。长度默认取数据区容量和 1023 帧上限的较小者；
`frames` 参数可指定更短长度。硬件 `EPDC_DEBUG_LUTn[14:5]` 是 10 位帧计数。

保存用户波形 2（GC16，映射硬件模式 2）所有温度档指针，临时指向合成表。
画布整屏写 `0x88`，FULL 提交形成当前色为 8、目标为 8 的不动 WB，
之后使用 `(LUT << 12) | 8 | 动作目标色` 写 WB，整个 LUT 期间不逐帧提交 ioctl。

## 状态、计算与写入

每像素状态占一字节，共 480 KB：位置在 `[4:0]`，目标为白在位 5，
当前 WB 动作在 `[7:6]`（0 不动、1 推白、2 推黑）。位置范围为 `0..top`，
`top = nps + 2 * extra`，最大为 31；默认 `extra=2`。

16 像素一组，用 NEON 朝黑或白端点走一步，只计算忙组。两端各有 `extra` 档补推区；
目标反转时先跳出补推区，立即反向。接收线程只保存最新完整视频帧；目标变化的 8 字节块
展开为 64 个目标位，并把对应四组标为忙。中间视频帧可以被新帧覆盖。

下一帧动作变化的组进入写表。扫描帧计数变化后，先把写表中目标色扩展成 16 位，
每组两次 16 字节 NEON 存储写入 WB，再取最新视频目标、计算下一帧。
只有整组当前动作和下一动作都不动才转为空闲。统计中的 writes 是 16 像素组写入次数。

## 重启与漏帧

长 LUT 完成后等待 marker，再 FULL 提交。处理阶段把 WB 目标重置为 8，
`resync()` 将写表及当前仍在推动的忙组重新写入。LUT 编号从活动位变化取得。
等待驱动工作线程启动 LUT 时每次睡眠 200 µs，让普通调度线程执行。

扫描帧计数一次前进超过 1 时，`catch_up()` 按 WB 中实际动作补算多执行帧的位移，
并饱和到端点。已算好的下一帧动作仍然写入，端点最多额外推一帧。
计算不能还原错过帧的中途目标变化；位置是估计，端点补推吸收部分漂移。

退出时将 WB 改为不动、等待长 LUT 完成、还原 GC16 指针，将位置阈值化画到画布，
以真实 GC16 刷一次，恢复画布格式和关电延迟，并设回 AUTOMATIC 模式。
模式 3 数据区内容由实验覆盖，实验后需重启恢复该区。

## 实时调度与统计

计算线程申请 `SCHED_FIFO` 优先级 50 和 `mlockall(MCL_CURRENT | MCL_FUTURE)`，
接收线程保持普通调度。失败会打印错误并继续运行。计算结束后适当睡眠，再轮询帧计数。

播放器保留 take_target、compute 的平均/最大耗时、计算线程 CPU 耗时、忙组数量、
写入平均/最大耗时、每秒决策数、漏帧与计算超时归因、首次启动和重启耗时，以及组写次数。

2026-10-06 的设备历史测量（30 秒动画，详见 [视频记录](experiments/2026-10-06-video.md)）：

| 内核 | 每秒决策 | 漏帧 | LUT 重启 | 计算 |
| --- | --- | --- | --- | --- |
| 无 Y8 快速路径与温度缓存的主线 | 83.1 | 6 | 100–260 ms/次 | 平均 2.6 ms/帧 |
| 含 Y8 快速路径与温度缓存（同锁定主线的功能） | 84.1 | 11 | 5–29 ms/次 | 硬件扫描约 84.7 帧/秒 |

WB 整屏写约 4.6 ms、零散 64 位写约 200 ns/次是设备微基准数据。

## 限制与验证边界

需要实际设备的波形已加载、mxcfb UAPI、root 权限和可访问 RAM 的 `/dev/mem`。
驱动不知晓波形指针和 WB 被改写；它与其它显示使用者不能协调。
合成表参数从启动时的温度档读取，播放途中不重算推动帧数。
没有直流平衡，静止像素为不动（0 V）；长时间播放的残影与寿命影响未验证。

`tests/test_k4wb.c` 包含实际播放器计算与写入函数，逐帧对照标量模型，覆盖随机矩形、
整屏翻转和模拟 LUT 重启。`test_neon.c` 覆盖不同补推参数的 NEON 与标量步进。
QEMU 对拍和 ARM 构建不能证明设备视觉效果、扫描同步、调度时延、电源或冷启动行为。
