# WB 逐像素直驱

`player/k4-wb.c` 接收 800×600、30 fps、MSB-first 的 monob TCP 字节流。
每帧 60000 字节，1 表示白、0 表示黑。软件在每个 EPDC 扫描帧决定推白、推黑或不动。
它通过 `/dev/k4-epdc-wb` 启动驱动管理的长 LUT 会话、mmap 工作缓冲，
以 WAIT_FRAME 等待 EOF 扫描帧边界。驱动负责波形合成、LUT 重启和会话结束。

## 工作缓冲格式

WB 每像素 16 位，小端；宽高、像素行步长和映射字节数由 START 返回。
播放器使用返回的完整 hold/black/white 值写入，不自行拼接 LUT 或当前色。

| 位 | 含义 |
| --- | --- |
| 15:12 | LUT 编号 |
| 11 | PARTIAL 处理中被选中的像素标记；FULL 不置位 |
| 10:8 | 本播放器保持为 0，未使用 |
| 7:4 | 目标灰度，动作表下标的高四位 |
| 3:0 | 当前灰度，动作表下标的低四位 |

每个扫描帧重读 WB，按 `(目标 << 4) | 当前` 索引活动 LUT 当帧的 256 字节动作表。
LUT 完成后 WB 保持原值，下次处理时旧目标成为当前灰度。
位定义来自探针实验；扫描机制依据 i.MX50 RM 24.3.8.1、24.3.8.4 与表 24-3。

## 合成表与启动

播放器保存画布格式，设 REGION 自动刷新模式、Y8 画布，以真实 GC16 整屏刷白并等待
完成，然后调用 `K4_EPDC_WB_START`。接口定义在内核的
`include/uapi/linux/k4-epdc-wb.h`；设备由 EPDC 核心注册。

START 阻止新普通更新并排空已有队列；按当前温度档 A2 序列的首个非零 `(0x0f)`、
`(0xf0)` 动作取得推黑、推白电极动作，以推白非零帧数返回 `push_frames`（即 `nps`）。
驱动在 probe 预留的独立波形 DMA 区构建 1023 帧合成表，每帧均为目标 0 推黑、15
推白、其它目标不动，对所有当前灰度一致。原厂波形及其模式/温度指针由波形加载器管理。

合成会话固定使用 LUT0、FULL 整屏，UPD_FIXED 固定当前色与目标色为 8（Y8 的
`0x88`），所有像素初始不动，不读取应用画布。START 返回时 WB 处理已完成，可按
返回的 size 在 offset 0 做共享 mmap。info 还包含 width、height、stride、完整
hold/black/white 值、frames_per_lut 和 push_frames；当前实现为 `0x0088`、`0x0008`、
`0x00f8`，播放器以返回值为准。会话保持持续上电；驱动仅在时钟已开启时访问寄存器。

同一时刻只有一个会话，第二个 START 返回 EBUSY。会话中 mxcfb SEND_UPDATE 与前端
自动刷新返回 EBUSY。设备 fd 是会话所有者；其它打开的 fd 不能 STOP 或映射该会话。

## 状态、计算与写入

每像素状态占一字节，共 480 KB：位置在 `[4:0]`，目标为白在位 5，
当前 WB 动作在 `[7:6]`（0 不动、1 推白、2 推黑）。位置范围为 `0..top`，
`top = nps + 2 * extra`，最大为 31；默认 `extra=2`。

16 像素一组，用 NEON 朝黑或白端点走一步，只计算忙组。两端各有 `extra` 档补推区；
目标反转时先跳出补推区，立即反向。接收线程只保存最新完整视频帧；目标变化的 8 字节块
展开为 64 个目标位，并把对应四组标为忙。中间视频帧可以被新帧覆盖。

下一帧动作变化的组进入写表。扫描帧计数变化后，先把写表中目标色扩展成 16 位，
每组两次 16 字节 NEON 存储写入 WB，再取最新视频目标、计算下一帧。
只有整组当前动作和下一动作都不动才转为空闲。统计中的 writes 是 16 像素组写入次数。

## 重启与漏帧

`K4_EPDC_WB_WAIT_FRAME` 为 IOWR，播放器输入上次返回的 frame 与 generation，每次
START 后首次将两者置 0。WB 处理完成后，累计帧号超过输入或 generation 变化时
立即返回；没有新进度时阻塞等待。计算期间已经经过的 EOF 可直接消费，避免额外
等待一整帧。输出为当前会话累计执行的 LUT 帧数与重启次数 generation。
信号中断返回 EINTR，等待期间会话停止或替换返回 ECANCELED（或硬件错误）。硬件 IRQ 根据
`EPDC_DEBUG_LUT0[14:5]` 的剩余帧数累计帧进度（RM 24.4.31），在每次 EOF 保持中断
启用并唤醒等待者；IRQ 直接记录进度，因此提交工作线程合并事件不丢帧。帧数跨重启
累计，重启间隙不计。

长 LUT 完成后核心提交工作线程立即以 LUT0 重提整屏不动，generation 增加。
播放器观察到 generation 变化时，`resync()` 将写表及当前仍在推动的忙组重新写入。
若帧号未前进，仅重写动作并继续等待帧进度，不额外步进位置。
WAIT_FRAME 在 WB 处理完成后返回已有进度或等待新进度，使恢复写入发生在 WB 处理之后。

累计帧差超过 1 时，`catch_up()` 按 WB 实际动作补算多执行帧的位移并饱和到端点。
已算好的下一帧动作仍然写入，端点最多额外推一帧。计算不能还原错过帧的中途目标变化；
位置是估计，端点补推吸收部分漂移。

退出时调用 STOP：驱动停止重启、撤销所有映射、将 WB 写成全部不动、等 LUT 排空，
恢复会话开始前的自动关电设置。播放器将位置阈值化画到 Y8 画布，用 GC16 整屏恢复，
还原画布格式并设置 AUTOMATIC 模式。核心置 `restore_pending`，下一次普通更新强制
FULL 整屏；SNAPSHOT 同时捕获整个画布，避免只恢复局部未知历史。

映射采用独立匿名 inode，与设备 fd 的引用分开。最后一个设备 fd 关闭自动 STOP，
即使 mmap 仍存在；挂起与设备移除也先 STOP。STOP 后旧映射访问产生 SIGBUS，需
munmap，新会话重新 mmap。已打开的设备文件保持已停止核心对象的生命周期，旧映射
只保留匿名 inode，控制器和映射排空后才能释放 DMA。

## 实时调度与统计

计算线程申请 `SCHED_FIFO` 优先级 50 和 `mlockall(MCL_CURRENT | MCL_FUTURE)`，
接收线程保持普通调度。失败会打印错误并继续运行。计算完成后阻塞等待 WAIT_FRAME。

播放器保留 take_target、compute 的平均/最大耗时、计算线程 CPU 耗时、忙组数量、
写入平均/最大耗时、每秒决策数、漏帧与计算超时归因、首次 START 耗时、重启次数及观察到重启时的帧边界等待耗时，
以及组写次数。边界等待包含正常扫描等待，不能单独代表驱动重启耗时。

2026-10-06 的设备历史测量（30 秒动画，详见 [视频记录](experiments/2026-10-06-video.md)）：

| 内核 | 每秒决策 | 漏帧 | LUT 重启 | 计算 |
| --- | --- | --- | --- | --- |
| 无 Y8 快速路径与温度缓存的主线 | 83.1 | 6 | 100–260 ms/次 | 平均 2.6 ms/帧 |
| 含 Y8 快速路径与温度缓存（同锁定主线的功能） | 84.1 | 11 | 5–29 ms/次 | 硬件扫描约 84.7 帧/秒 |

WB 整屏写约 4.6 ms、零散 64 位写约 200 ns/次是设备微基准数据。

## 限制与验证边界

需要匹配的 EPDC WB 补丁、面板波形、mxcfb UAPI、root 权限和 `/dev/k4-epdc-wb`。
合成表参数从启动时的温度档读取，播放途中不重算推动帧数。
没有直流平衡，静止像素为不动（0 V）；长时间播放的残影与寿命影响未验证。

`tests/test_k4wb.c` 包含实际播放器计算与写入函数，逐帧对照标量模型，覆盖随机矩形、
整屏翻转、模拟 LUT 重启以及完整 16 位 info 动作值写入。`test_neon.c` 覆盖不同补推参数的 NEON 与标量步进。
内核主机模型覆盖 START/STOP、自动重启、EOF 累计、更新互斥、关闭/挂起停止、映射
拒绝与撤销，以及 STOP 后整屏恢复。QEMU 对拍和 ARM 构建不能证明设备视觉效果、扫描同步、调度时延、电源或冷启动行为。
